Why Privo

MCP gave your team’s AI real access. Privo gives you the controls.

The Model Context Protocol lets Claude, ChatGPT, Cursor and the rest use your real tools: your repositories, issues, databases and payments. That is the point. It is also the risk.

Without PrivoWith Privo

Without Privo: Keys everywhere

Every person pastes an API key for every tool into every AI client’s config file.

With Privo: One sealed vault

Credentials live encrypted in one place. Each AI client holds a single Privo token, or signs in.

Without Privo: Tools change underneath you

A server can rewrite a tool’s description at any time, and your AI reads it as instructions.

With Privo: Changed tools wait for review

A new or changed tool stays hidden from everyone until a person accepts it.

Without Privo: Nobody in the loop

An agent can merge, refund or delete, with no one watching and no one asked.

With Privo: Rules and approvals

Allow, ask or deny by server, tool, team and even the call’s arguments. Risky calls wait for a person.

Without Privo: No record

When something goes wrong, nobody can say what the AI did, or as whom.

With Privo: An audit trail you can prove

Who called, from which client, what ran, who approved it and how it ended, sealed into signed blocks.

Get started

From nothing to your team’s first call.

One binary on your server, a few minutes in the browser, then one line in each AI client.

  1. 1

    Admin · on the server

    Run Privo

    One static binary with its own database. Give it a master key and a folder for its data.

    $ bin/privo serve
  2. 2

    Admin · in the browser

    Become the owner

    Connect a GitHub OAuth app, print a one-time setup link and sign in with your GitHub account.

    $ privo admin setup-link
  3. 3

    Admin · in the browser

    Add servers

    Pick from the built-in catalog or add any remote MCP server, then choose which teams reach each one.

    GitHubLinearSentryFigmaNotionSlack+18
  4. 4

    Admin · in the browser

    Invite your team

    Send each person a one-time link and give them roles: member, approver, auditor.

    $ privo admin invite --person ada
  5. 5

    Everyone · once

    Connect your own accounts

    Each person signs in to the servers that should see them as themselves, or enters their own API key.

    GitHub connectedLinear connectedSentry connect →
  6. 6

    Everyone · in their AI client

    Point your client at Privo

    The Tokens page gives each person a ready line for their client, or clients can sign in with OAuth.

One line in each AI client

Every client talks to the same address. Only the token is personal, and it reaches nothing but /mcp.

Run in a terminal:

claude mcp add --transport http privo https://privo.example.com/mcp --header "Authorization: Bearer <your token>"

Add to ~/.cursor/mcp.json:

{
  "mcpServers": {
    "privo": {
      "url": "https://privo.example.com/mcp",
      "headers": { "Authorization": "Bearer <your token>" }
    }
  }
}

Add to .vscode/mcp.json, or your user mcp.json:

{
  "servers": {
    "privo": {
      "type": "http",
      "url": "https://privo.example.com/mcp",
      "headers": { "Authorization": "Bearer <your token>" }
    }
  }
}

Add to ~/.codex/config.toml, and keep the token in PRIVO_TOKEN:

[mcp_servers.privo]
url = "https://privo.example.com/mcp"
bearer_token_env_var = "PRIVO_TOKEN"

Add to ~/.codeium/windsurf/mcp_config.json:

{
  "mcpServers": {
    "privo": {
      "serverUrl": "https://privo.example.com/mcp",
      "headers": { "Authorization": "Bearer <your token>" }
    }
  }
}

Your address and token come from the Tokens page, filled in. With OAuth switched on, clients such as Claude Code, ChatGPT and VS Code need no token at all: they sign in through the browser.

Security

Built to guard the keys, because it holds them.

Privo keeps your team’s credentials and decides what AI may do with them. So every default fails closed.

Sealed at rest

AES-256-GCM envelope encryption with a key per organisation. The master key never touches the database, and a backup is useless without it.

Never handed out

A credential is opened for one call. It is never returned by the API, written to a log or shown to an AI client.

Closed by default

Unknown tools don’t exist. Unreviewed tools stay hidden. Local command servers are refused unless you allow them. Waiting approvals expire.

No surprise destinations

Outbound requests refuse loopback, private and link-local addresses, cloud metadata included, unless you allow a network.

An audit you can check

Every call and every admin change is recorded before it runs. Run privo audit verify on the host, or check from the Activity page.

Reviewed in the open

Changes to sign-in, secrets, tenancy and the request path get a separate security review, and the reports are published in the repository.

FAQ

Questions, answered.

What is MCP?

The Model Context Protocol is an open standard that lets AI assistants such as Claude, ChatGPT and Cursor use outside tools and data: your repositories, issues, documents and databases. An MCP server is the bridge to one of those tools.

Who is Privo for?

Teams who let AI assistants use real tools: startups, agencies and growing companies that want one place to decide what AI may do, a person in the loop for risky calls, and a record of what happened.

Which AI clients work with Privo?

Any client that speaks MCP over Streamable HTTP: Claude Code, Claude, ChatGPT, Cursor, VS Code, Codex, Windsurf, Zed, GitHub Copilot CLI and more. Clients that support OAuth can sign in instead of using a token.

Which MCP servers can I put behind it?

Any remote MCP server over HTTP or SSE, with a key the whole team shares, each person’s own account (OAuth) or each person’s own API key. Local command (stdio) servers are for development for now.

Does anything leave my server?

No. Privo sends no telemetry. Call statistics stay in your own database, and Prometheus metrics are served only on an address you choose.

Is it free?

Yes. Privo is open source under the MIT License, and running it on your own servers costs nothing. Privo Cloud, the hosted version, is not open yet: join the waitlist.

How ready is it?

Privo is in early development, before 1.0. It is tested end to end with a real MCP client against the built binary, and every decision and security review is in the repository. Pin a version and read the upgrade notes before you update.

How do I report a vulnerability?

Privately, through GitHub’s private vulnerability reporting, never in a public issue. The security policy has the details.
